# Shop delivery line — implementation note, 16 November 2026

Owner request (16 Nov): bring the competitor apps' features into Wind, decide by recommendation, leave nothing half done.
This note records what the shop line does, the decisions taken by recommendation, and what is still gated.

Sources:
- SRS `docs/requirements/SRS-2026-11-16-wind-one-app.md`: §7 DLV, §7.1 MER, §2.1/2.1a, §16a D-1/D-2, ADM-12.
- The five demo apps in `Documents/wind-competitors`: HAAT, Souq, Careem, Uber, Shiply.
- A Grok 4.7 build spec written for this pass. Behaviour is copied; no code, strings or art.

## Switch

The line is off by default and invisible (ONE-13). It turns on only when `WIND_ENABLED_SERVICES` lists `shop`. `WIND_SHOP_TOWN=<city id>` limits it to one pilot town, as decided in D-2.

**Do not enable it in production yet.** D-2 holds the first real shop order until PostgreSQL, off-host backup and a restore drill are in place. The code runs on both SQLite and PostgreSQL (migration 33, `server/db/postgres-shop.sql`).

## What it does

| Area | Behaviour | SRS |
|---|---|---|
| Shops | A customer account applies with name, category, pin, phone and trade licence. An admin approves it and sets the minimum, fees and commission. An expired licence pauses the shop at the next sweep. Merchant mode lives inside the same account, reached from Account. | ACC-06, MER-05, MER-08 |
| Categories | Grocery, bakery and everyday goods only. Pharmacy and tobacco are refused (`category_closed`). | DLV-19 |
| Catalogue | Sections and items with integer-agorot prices, sold by weight or by the piece, plus an out-of-stock switch. Opening hours run past midnight. The shop can pause new orders without cancelling accepted ones. | DLV-01, MER-02 |
| Cart | One shop per cart, with a confirmation before switching shops. Each line carries a choice for when the item is missing: remove, ask me first, or similar. The cart is kept on the device. | DLV-02, DLV-05, A11Y-14 |
| Placing | The server prices the basket, checks the money minimum, refuses promos (`promo_wrong_service`), keeps delivery inside one town, and applies the PAY-09 pause. The agreed limit for weighed goods (0, 10% or 20%) is stored as a goods cap. The cap plus both fees must stay under the ADM-12 cash ceiling. Placing is idempotent on `requestId`. | DLV-03/04, ADM-12, PAY-09 |
| Order states | `requested`, the one new spine status, means waiting for the shop. The shop's own progress is a separate field: `accepted → preparing ⇄ awaiting_approval → ready → handed_over`. Every state names who acts, in Arabic and English. | ONE-03/04, DLV-08/09 |
| Accept | The shop has 5 minutes and can add 5 more once. With no answer the order is cancelled `accept_expired` at no charge. The shop gives preparation minutes on accepting, or declines with one of three typed reasons. | DLV-07 |
| Cancel | The customer cancels free until the shop accepts. While the shop has only accepted, support can cancel at the customer's request. From `preparing` on, there is no customer-requested cancel. Operators cancel only for `no_captain`, `operational`, the shop's request or an unresolved handover problem, always with a note. Only the server sets `below_minimum`. | DLV-11, DLV-23, D-2 |
| Changes | Weight, substitution and removal are checked in the SRS order: ceiling, then ask-first, then minimum, then goods cap. An approval raises the cap and never lowers it. A decline or a 5-minute timeout removes the line. Time spent waiting for the customer moves dispatch back. Every change appends a snapshot. | DLV-04/05/06/10 |
| Ready | Ready requires every weighed line's actual weight and the packing record (sealed packages, and the items in each open bag). Marking ready early starts the captain search at once. | MER-03, DLV-12 |
| Dispatch | Captains are sought so they arrive around the ready time. If no captain is found 10 minutes after ready, the customer, the shop and support are told once. The order is never cancelled automatically. The 24-hour stale-order sweep skips shop orders. One shop order per trip. | DLV-12, DLV-24 |
| Captain at the shop | The shop's own 4-digit code has a 5-miss lockout on a counter separate from the delivery code, and support can reset it (audited). The captain checks the packages and the open bags. A problem report sends the shop back to preparing. A captain cannot cancel at the shop, and a job the captain holds cannot be released. | DLV-13, §2.1, DRV-17 |
| Delivery | Each sealed package is recorded intact or broken (append-only), then the customer's delivery code is entered. Cash at the door is goods plus delivery fee plus service fee, with the existing A11 variance rules. | DLV-14/15 |
| Failure | After collection a failure puts the order on hold. Support sends it back to the shop with a return code that only the shop holds. Only `rescheduled` may get one more attempt. A returned order earns no commission, and the captain is paid the trip and the return leg from operating expenses. | DLV-20/21/25, DRV-17 |
| Money | `shop_ledger` is append-only with books `merchant`, `captain` and `wind`. A completed order credits the shop's goods and debits the shop commission. The service fee and the commission go to Wind. Captain commission is on the delivery fee only. The goods and service fee are added to what the captain owes Wind, and the goods count in the cash cap. With shop on, the cap defaults to ₪1,000 and must be at least the order ceiling. | DLV-15, PAY-05, ONE-10, CON-05, ADM-12 |
| Settlement | Support records the fault result once (`merchant`, `wind` or `none`). Unsellable returned goods are credited to the shop only when the fault is not the shop's. A refund is paid by whoever is at fault. A payout needs a reference and never exceeds what Wind has received in cash. | DLV-22/25, MER-04/07/09 |
| Ratings | The customer rates the shop and the shop rates the customer, once each, separately from the captain. | CON-08 |
| Order again | The cart is rebuilt from today's prices and stock and shows what changed. Order again never places by itself. | DLV-18 |
| Support list | `GET /api/admin/shop/attention` lists: no captain, an open handover problem, a locked pickup code, and failed orders with no fault result after 2 days. | DLV-12/13/22 |

## Decisions taken by recommendation

1. **Merchant mode is a link inside the customer account**, not a fourth role. The `users.role` check stays `customer | driver | admin` (MER-05, ONE-01).
2. **One town per order.** The drop-off must be in the shop's town. This also keeps bicycles in town without a separate rule (§2.3).
3. **The shop is credited when the order completes. A payout waits until the captain who collected the cash owes Wind nothing.** The SRS credits at the captain's handover. Wind's cash handovers are not matched to individual orders, so "the captain owes nothing" is the strict form of that rule. `ponytail:` it holds back all of that captain's goods for that shop. Order-by-order matching of handovers would release some earlier.
4. **Captain pay for a stop at the shop** is the delivery fee once the captain is at the shop, and nothing before. `ponytail:` "trip so far" needs measured distance, which comes with live tracking on PostgreSQL.
5. **Agreed limit choices** are exact, +10% (default, `shopAgreeLimit`) and +20%. The server accepts anything from 0 to 50%.
6. **Five wrong tries lock a code**, Wind's SHIP-05 value, rather than Souq's three.

## Review fixes (16 Nov, PR #74)

A second review of #72 and #73 found these, now fixed:

- **Goods COD and the ceiling.** Every fare write after booking adds the order's goods COD before the ADM-12 check: the destination quote and accept, the driver offer and the customer's accept of it. A fare going back to the pool (release, courier block) is `min(recommendation, ceiling − COD)`. If a lowered ceiling leaves no room, the booked fare stays, and a release or a courier block is never refused.
- **No COD on shop orders.** The shop ledger collects the goods, so parcel COD on a shop order is `409 cod_unavailable`.
- **Over-collection.** The captain owes all door cash above the delivery fee. The excess is a `door_over` row (owed back to the customer) and a credit on `platform:customer_overpay`. Paying it back is a manual office step for now.
- **Refunds** need a `requestId`. A replay with the same id returns the order, and a replay with a different amount or reason is `409 idempotency_conflict`.
- **Screens.** After a failed delivery, the customer card names on hold, returning or returned. Admin cancel offers only the reasons allowed now. The Activate button, like Save, stays disabled until the terms are valid. The substitute list is uncapped. The merchant's rating of the customer sticks. Closed shops show today's hours and open for browsing. Merchants set one daily opening range. The Shops tab lists the orders that need attention.

Deliberately unchanged:
- A ceiling lowered below an order that is already booked does not block a driver from taking it at the booked fare. Only changes are refused (ADM-12: consent and route changes).
- Refusing a ceiling above the captain cap stays tied to shop being enabled, until goods COD gets its own switch.
