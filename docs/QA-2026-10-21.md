# Wind scenario review — 21 October 2026

## Result and scope

The local customer, driver, recipient and administrator journeys passed against
isolated SQLite databases. The review includes real browser interactions, the
actual API, map downloads and the connected Samsung A53's Chrome. It does not
certify a new native APK, iOS device build, production deployment or real payment.

Workspace: Expo SDK 57, Android version 1.0.12 / code 13. The attached A53 had
1.0.11 / code 12 installed; physical checks used the latest local web export in
Chrome. No production orders, external messages, payments or deployments were made.

The desktop scenarios use controlled GPS samples and a local OSRM fixture. MapLibre,
its worker, styles, fonts and OpenFreeMap tiles load from their actual URLs. Route
fixture success establishes application behavior, not real-road travel accuracy.

## Fixes

| Issue | Change | Verification |
|---|---|---|
| Fresh driver GPS could be discarded while an older upload was pending | Keep the newest pending browser fix and upload it after the in-flight request | Browser regression delays the first, rejected pre-assignment fix, injects a fresh point, then verifies the customer receives it |
| An HTTP 200 for an ignored GPS sample incorrectly counted as successful sharing | API returns an additive `accepted` flag; web and native clients acknowledge only accepted samples; native malformed receipts remain retryable | API, background delivery and registered native-task tests cover old, reordered and accepted fixes |
| Native pickup permission could leave the location request waiting indefinitely | Include permission acquisition in the pickup deadline and cancellation; late permission cannot start a watch | Pickup tests cover permission timeout, late grant, denial, successful grant and watch cleanup |
| Android map said ready while tiles were still loading | Send the WebView `ready` signal after MapLibre's load event; retain the failure deadline through tile loading | Delayed tile downloads reproduced the old failure; the scenario now requires no premature ready signal |
| Ride boarding used parcel pickup wording | Add English and Arabic passenger-boarding text to the ride action | Browser ride journey boards and completes without a parcel handover code; typecheck/lint |
| Missing Router linking dependency and SDK patch mismatches | Install the SDK-compatible `expo-linking` dependency and update Expo/location/router/splash packages with Expo install | Expo Doctor 21/21; web export and Android/iOS Hermes exports; typecheck/lint |
| Repeatable cross-role checks were missing and backlog/docs were stale | Add browser and physical Android test commands; distinguish historical plans from verified behavior and unfinished work | Scenario outputs below; README commands run against isolated local data |

Existing in-progress map and pickup-selection changes were retained and exercised,
including chosen-city gating, city selection from a GPS fix, removal of an old
landmark when the city changes, accuracy handling, map framing and retry behavior.

## What remains

1. **Rebuilt native runtime checks:** install the current APK and run screen-locked
   tracking, background/resume, force-stop/relaunch, permission revoke and logout
   on the A53. Exercise the current iOS build on an iOS device. Bundle export and
   task mocks do not substitute for these OS-level checks.
2. **Native push:** EAS project/Expo account and FCM v1 credentials are still needed
   for integration and delivery verification. Web Push exists and has automated tests.
3. **Phone verification and digital payments:** self-service contacts remain
   unverified; SMS gateway and licensed payment provider integration are absent.
   Tested delivery settlement is cash, with no real money moved in this review.
4. **Deployment validation:** these local fixes need a separately authorized release,
   then production routing/tiles and GPS checks. No current-production claim is made.
5. **Upstream dependency advisories:** `npm audit` reports 19 high entries stemming
   from two transitive tooling advisories: [braces](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)
   and [node-forge](https://github.com/advisories/GHSA-86w9-cpqp-85rv).
   The audit provides no SDK-57-compatible upgrade; its proposed Expo 44 downgrade
   was not applied. [Audit evidence](../.expo/scenario-audit.json).

Owner-deferred features remain separate from defects: sender goods-price payouts,
digital tips, delivery photos, identity-document uploads and cancellation fees.
This review does not enable them or broaden the default parcel-only service setting.
