## Operational defaults and measured boundaries

PostgreSQL pool: at most8 clients, acquisition timeout1000ms, statement timeout5000ms, lock timeout500ms, idle transaction timeout10000ms and idle pool timeout30000ms. Positive integer bounds are validated. Every explicit transaction retains exactly one client until commit/rollback, including across awaits. Ordinary nontransactional statements are separately autocommitted, preserving legacy error-side-effect semantics. Nested transactions are rejected; no savepoint API is implied.

Retry policy: only caller-certified, database-only `transaction(..., {commandId, replaySafe:true})` units may retry SQLSTATE40001 or40P01, at most3 attempts with10/20ms bounded waits. The command ID is passed unchanged on every attempt. Unsafe units run once. Request handlers are not automatically retried. Connection loss, statement/lock timeout and unknown commit outcomes are never replayed. Migration lock lifetime equals its transaction; losing the connection releases the PostgreSQL lock.

SQLite retains WAL/FULL/foreign-key settings and250ms external busy timeout. Its async adapter serializes connection access through an ownership queue with1000ms acquisition timeout; an awaited transaction cannot expose its rows or accept another request's COMMIT/ROLLBACK. Sync fixture writes must be performed offline, never concurrently with handlers. SQLite is still a single-process API deployment target; the multiprocess test is race evidence, not rollout permission.

Real tests measured/required a pool acquisition rejection under1000ms with a100ms configured limit, an80ms statement timeout, a60ms contested row-lock timeout, one actual deadlock victim/one retry, and nonoverlapping advisory-locked migration critical sections from independently pooled runners. Geographic proof uses `ST_SetSRID(ST_MakePoint(longitude, latitude),4326)` and verifies X=35.2/Y=31.9/SRID4326. No production geometry schema is claimed.
