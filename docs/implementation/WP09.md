# WP09 backend: session-bound native push attempts and authorized realtime credentials, provider gates open

Migration 12 adds `native_push_tokens` after migration 11 (WP08 quotes, verified as the maximum in `server/db/postgres-schema.ts` before starting): `token_hash` (SHA-256 of the Expo token) as primary key, `user_id`, `auth_session_hash`, `device_hash` unique per physical device, `platform` (`ios`/`android`), the raw `expo_push_token`, `lang`, `prefs_json`, `created_at`/`updated_at`, and nullable `disabled_at`, with `FOREIGN KEY(auth_session_hash, user_id) REFERENCES sessions(token_hash, user_id) ON DELETE CASCADE` mirroring presence (migration 9), plus a trigger that deletes a blocked account's tokens. The table is allowlisted in `server/migrate.ts` so PostgreSQL import does not demand it from a SQLite snapshot. SQLite creates no native table and the frozen SQLite schema is unchanged: native registration is PostgreSQL-durable only and returns `409 native_push_unavailable` there, following the presence/phone durable-protocol precedent, while the installed browser Web Push keeps its legacy best-effort SQLite behaviour untouched. `POST /api/push/native/register` validates the `ExponentPushToken[…]`/`ExpoPushToken[…]` format, a UUID `deviceId`, platform and language, binds the row to the caller's current session hash inside the request transaction, and upserts per device: a rotated token replaces the old one and registering the same device or token under a new account retires the previous account's binding. `POST /api/push/native/unregister` deletes the caller's device idempotently (the client unregisters before sign-out, as designed), and `POST /api/push/native/preferences` replaces `{nonessentialMuted, mutedKinds, quietHours{startMinute, endMinute, utcOffsetMinutes}}` and can soft-disable via `disabled`. Because every revocation path already deletes sessions — logout, email/phone password reset, password change (other sessions), account deletion, admin block/role/password actions, and phone change/recovery in `server/domain/phone-identity.ts` — the foreign key revokes native tokens with no per-path code; the tests exercise each HTTP path and the exact session deletion the phone/reset paths perform.

On PostgreSQL, `enqueuePush` (`server/domain/events.ts`) now writes `expon:{userId}:{tokenHashPrefix16}` destinations for enabled tokens in the same transaction and event as the existing `webpush:` destinations, so a rolled-back mutation leaves neither, and `newJobPush` also reaches native-only drivers. `DurableWorker` resolves `expon:` destinations with the same TTL (job 300 s / offer 600 s / else 3600 s), assignment-epoch, role, participant and lifecycle rechecks as Web Push, then suppresses disabled tokens and preference-muted, nonessential-muted, and quiet-hours hints as `obsolete` (essential kinds bypass quiet/nonessential muting), and suppresses expired offers whose order left `searching` or whose TTL elapsed. `DeviceNotRegistered` and malformed stored tokens delete the token and go `obsolete`; transient provider failures reuse the existing doubling backoff (capped 1 h plus jitter) and exhaust to the `review` operator queue; poison destinations also land in `review`. Delivery goes through the injectable `expoTransport` (deterministic fakes in tests only). The built-in Expo sender stays disabled unless `WIND_EXPO_PUSH_ENABLED=1` is set with owner credentials: without it every attempt fails as `provider_http_503` into backoff/`review` and is never marked delivered. No test makes a real Expo, FCM, or APNs call, and push payloads carry only `{kind, order, url, lang, eventId}` — a hint, never authority.

`server/domain/realtime.ts` adds `GET /api/orders/:id/realtime` minting a five-minute HMAC credential (`{url, token, group:"order-{id}", expiresAt, serverTime, eventCursor, assignmentEpoch, version, snapshotPath, livePath, transport}`) for the order's customer, assigned driver, or an admin only, and a public `GET /api/track/([a-f0-9]{64})/realtime` variant scoped to the `trackView` allowlist (searching/active, or finished within the one-day grace) that names no participant. Verification — the fake-hub gate in tests — re-reads the session/share hash, account status, and current assignment on every use, so a revoked session, a released driver, or a revoked share link loses access before expiry; tampered credentials are `realtime_invalid` and elapsed ones `realtime_expired`. Events already carry `sequence` and `assignmentEpoch` via `publicEvent`, `orderProtocol` snapshots now also carry `serverTime`, and clients resync after a gap with the existing `GET /api/orders/:id?protocol=1&after=` snapshot, which remains authoritative; the long-poll `liveFix` endpoints are unchanged as the fallback. Without `WIND_PUBSUB_ENDPOINT` plus `WIND_PUBSUB_ENABLED=1` the credential honestly reports `transport:"long_poll"` with `url:null` — no Web PubSub connection is claimed. Client native wiring was not landed: Expo SDK 57 (`expo ~57.0.31`, versioned docs checked) requires an EAS `projectId` for `getExpoPushTokenAsync`, FCM/APNs credentials for the Expo backend, and a development build (remote push is unavailable in Expo Go on Android since SDK 53), and `app.json` has no `projectId` or notifications plugin — the standing blocker in `CAPABILITY-MAP.md:32`. No `expo-notifications` install, no `src/` or visual/copy change was made; the order-screen states remain Haiku's design (`docs/implementation/design-wp08-wp10.md` section 4) awaiting those fields, which WP10 can now consume (`sequence`/`assignmentEpoch` carriage, `serverTime`, durable attempts with expired-offer suppression) without WP09 inventing any `order.dispatch` shape.

## API contract

`POST /api/push/native/register` with `{expoPushToken, deviceId, platform, lang?, prefs?}` returns `{ok, registered, platform, lang, prefs}` or `400 invalid_expo_token`/`400 invalid_input`, `401 unauthorized`, `409 native_push_unavailable`. `POST /api/push/native/unregister` with `{deviceId}` returns `{ok, unregistered, removed}`. `POST /api/push/native/preferences` with `{deviceId, prefs?, disabled?}` returns `{ok, prefs, disabled}` or `404 not_found` for an unregistered device. `GET /api/orders/:id/realtime` returns the credential above or `401 unauthorized`, `404 not_found` for non-participants, `409 durable_protocol_unavailable` without the durable protocol. `GET /api/track/:token/realtime` returns the share-scoped credential or `404 not_found`. Snapshot resync stays `GET /api/orders/:id?protocol=1&after=` with `snapshotRequired`, per-event `sequence`/`assignmentEpoch`, and `serverTime`.
