## Issues, changes and verification

### 1. Disabled buttons looked like a grey wash with white labels
- Issue: `Press` set `opacity: 0.5` on every disabled control. A disabled forest primary button became mid-grey (`#899A94` on white) with white text: **2.95:1**, below the 4.5:1 needed for 15pt text. This is the grey accept button in `ar/driver-jobs.png` (design.md O6). It is a shared root cause: every disabled `Button` in the app had it.
- Change (`src/ui.tsx`): `Press` takes a `dim` prop (default `true`, so other callers are unchanged). `Button` passes `dim={false}` and draws its own disabled state: paper fill, secondary text (**5.61:1** on paper), the existing 1pt `line` edge, and the trailing price in secondary. A busy button (`loading`) keeps its colours and spinner, so work in progress does not read as locked.
- Verification: WCAG contrast computed from `palette` values: secondary on paper 5.61:1; the old wash fails at 2.95:1. Visible in `docs/screens/ar/driver-jobs.png` and `docs/screens/en/driver-jobs.png` (disabled Accept and offer buttons are paper with secondary text).

### 2. A disabled action gave no reason
- Issue: design.md §10 requires a visible 14pt reason under any disabled action. None existed.
- Change (`src/ui.tsx`): new `Reason` component (`Txt body`, secondary, 6pt top margin, aligned by language through `Txt`). Text, not a tooltip. `Button` takes an optional `reason` prop and renders `<Reason>` under itself only while it is disabled and not busy itself. Busy buttons show their spinner instead.
- Verification: see item 6 for the coverage count. Copy keys exist in both `ar` and `en` (`en: Copy` is typed, so a missing English key fails `npm run typecheck`).

### 3. Booking footer showed dots while quoting; no price when the route is unknown
- Issue: `trailing` was `'…'` while the route was unset or the quote loading (design.md §5: "never show dots alone"). The smart price card also showed `…`.
- Change (`src/app/book.tsx`): the footer price shows only when a route is chosen and the quote is current (`routeChosen && !quoting`). Under the Request button one reason line: `form_loading` while the form loads, `locating` while GPS runs, `quote_pick_route` before a route is chosen (the button stays enabled and opens the picker), `quote_calculating` while the price is worked out, `serviceUnavailable` when the service is off. The smart price card shows "نحسب السعر…" / "Calculating price…" instead of `…`. The promo-apply buttons use one shared lock reason (`lockedReason`).
- Not built: the 14pt muted skeleton bar from design.md §5. The text reason carries the state, which the design allows.
- Verification: `docs/screens/ar/book-calculating.png` and `docs/screens/en/book-calculating.png`, both from the official script with the quote request held for 9 s. Request is disabled in the paper style, the calculating reason sits beneath it, and no price is shown. Both were viewed.

### 4. Loading state was dimmed like a disabled state
- Issue: `Button` used `disabled || loading` for `Press`, so a busy button was dimmed the same way as a disabled one.
- Change: busy buttons keep full tone colours and the spinner (see item 1). Taps are still blocked while busy.
- Verification: as item 1.

### 5. Palette contrast
- Checked every text pair in the owned files against WCAG (`clayInk` on `clayPale` 4.81; `onFill` on `clayInk` 5.68; `olive` on `olivePale` 4.53; `secondary` on `muted` 5.13; `secondary` on `line` 4.80; `lime` on `forest` 10.81; `onFill` on `forest` 13.55).
- Failing pair found: the disabled wash (item 1), now replaced.
- Design-level pairs that fail (`faint` on `olivePale` 4.25; `clay` on `clayPale` 3.17 as text): no edited file uses them as text. `faint` appears only on icons and placeholders in those files. Not changed.
- Verification: arithmetic from the `palette` values.

### 6. Disabled buttons across the app had no reason (design §10)
- Issue: 47 `<Button ... disabled>` elements existed across `src/`. Four were owned and used inline `<Reason>`; 43 in other files had none.
- Change: every site now passes a `reason` prop (or has an inline `<Reason>`). Reasons come from existing or new copy keys in `copy.ts`: `wait_busy` for busy-driven disables, validation keys (`reason_min5`, `reason_min10`, `code_six_digits`, `promo_need_code`, `time_unchanged`, `profile_unchanged`, `email_unchanged`, `road_need_cities`, `road_need_name`, `password_rule`, `cash_none_owed`, `cash_amount_needed`), `pin_wait` for the map sheet, and the driver custody keys for the order-screen Accept.
- Verification: a parser over `src/**/*.tsx` finds 47 disabled Button elements. Of those, 43 carry a `reason` prop; the 4 owned ones (`book.tsx` Request, `driver/index.tsx` send offer / accept / ghost offer) show their reason through inline `<Reason>` lines, so none is left without one.
- Files touched in this item (beyond the four original owned files): `src/app/order/[id].tsx`, `src/app/admin/cash.tsx`, `src/app/admin/orders.tsx`, `src/app/admin/settings.tsx`, `src/app/admin/users.tsx`, `src/app/auth.tsx`, `src/app/driver/earnings.tsx`, `src/app/profile.tsx`, `src/app/roads.tsx`, `src/parts.tsx`, `src/pin-sheet.tsx`. Each edit is one prop or one ternary; no layout or handler changed.

### 7. Reason for an out-of-range offer (design §6, §10)

- Verification: `docs/screens/ar/driver-jobs.png` and `docs/screens/en/driver-jobs.png` (seeded driver carrying one order): both ride offers show the reason beneath their Accept and offer buttons ("أكمل طلباتك الحالية أولاً." / "Finish your current jobs first.").

## Behaviour preserved
- No new server fields or calls. The quote is still the server quote from `/api/price`, and `err_price_changed` handling is unchanged.
- No expiry or countdown control was added. The 120-second quote lifetime and the 15-second offer lease are server policy, and the server does not send those fields yet.

- Arabic is the default. Reason sentences exist in Arabic and English; Arabic is written in MSA and is not yet native-reviewed (design.md O5).

## Limits (honest)
- Not a device check. These are seeded browser captures, not native. Colour reads, text wrap at font scale 1.3, and RTL placement of the reason lines still need an Android and iOS pass (TalkBack/VoiceOver).
- The state captures depend on test-only setup inside `scripts/screens.mjs`: a smart-priced ride from the seeded customer and a freshly registered, approved driver. They run after the other driver scenarios, so the existing captures are not changed by them.
- The send-offer reason repeats the caption and the field error above it when the price is out of range. Intentional, to satisfy the reason rule.
- `busy`-driven reasons say "Another action is running. Wait a moment." Generic, by design.
- Button `variant="outline"` and `ghost` also change to paper when disabled. The outline edge is kept.
- Arabic reason sentences are unreviewed (design.md O5).
- Expo/RN: RN 0.86 and React 19.2.3 confirmed from the SDK 57 page (`https://docs.expo.dev/versions/v57.0.0/`). The changed APIs are React Native core (`Pressable`, `Text`, `accessibilityState`), which the SDK 57 page does not change. No Expo module was added or changed.
- Earlier in this task, `npm run screens` failed twice with `UNKNOWN: unknown error, open …` on `docs/screens` files (the repo sits in OneDrive). The third and final runs succeeded without intervention. The cause was not confirmed.
