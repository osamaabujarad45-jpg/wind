# WP07 backend: presence slice, integration incomplete

Migration 9 adds empty presence-session, latest-location and consent-audit tables after migration 8. It creates no online drivers and enables no GPS collection or dispatch. Legacy import classifies the three tables as auxiliary. A presence row is constrained to an authentication session belonging to the same driver; a latest fix is constrained to that driver's presence row. Deleting the authentication session or changing the user to an ineligible role/status cascades removal of the presence row and its latest fix.

The PostgreSQL-only, authenticated `/api/driver/presence` slice now has self status and online, offline, heartbeat and preassignment location endpoints. Online requires explicit `consentVersion:1`, a stable UUID command ID and device UUID; a different device cannot replace a live lease. The UUID is a client identifier, not device attestation. Online/offline receipts are idempotent and bound to the current authentication session; an online replay after its session expires fails closed. Heartbeats require monotonically increasing sequence numbers and renew a 60-second lease; a duplicate does not extend it. Location has its own sequence, accepts only fixes at most 30 seconds old and no older than the current presence session, enforces a two-second accepted-fix floor, uses server receipt time minus reported age, and retains only the latest fix. Stale, rate-limited and outlier fixes consume their sequence number. An absolute 70 m/s movement cap uses the smaller of the effective-fix interval and server receipt interval, so neither claimed accuracy nor a change in reported age can justify an impossible jump; a first fix and plausible spoofed motion are still untrusted. Accuracy and heading of -1 mean unknown. Online, heartbeat and location recheck the current session, driver and vehicle approval, current documents, policy and recorded revisions; offline deliberately remains available when eligibility or permanent approval has changed. Offline removes the preassignment fix. Account suspension and authentication-session deletion cascade removal. A self status returns no coordinates and explicitly reports `eligibleForMatching:false` because dispatch is not enabled.

The existing `/api/location` active-job endpoint retains its installed request shape. PostgreSQL uploads now lock current active orders and recheck and lock the authentication session before writing. Order and safety reads suppress a driver fix whose effective time predates that particular order's assignment, including when a driver is carrying multiple parcels. This is a partial hardening only: it does not add device, sequence or assignment-epoch fencing. A legacy callback has no assignment identifier and can still be indistinguishable from a current callback after reassignment to the same driver; timestamps alone cannot close that gap, including same-millisecond assignments. The new active-job protocol, automatic matching and eligible-driver shortlist remain unimplemented. Do not use these tables for dispatch until those pieces and independent review are complete. While an API server is listening, bounded maintenance runs at startup and every 15 seconds, marking expired or ineligible sessions offline and deleting their latest coordinates; it also deletes fixes older than 30 seconds even while a heartbeat remains active. It processes at most 1,000 sessions and 1,000 stale fixes per run; a backlog, database outage or stopped server can delay deletion. All consumers must enforce current lease, freshness and authority rather than infer readiness from a stored pin.

Outstanding work includes active-job device, sequence and assignment-epoch fencing, further revocation and poor-network coverage, native-device testing, and native review of the Arabic copy. The installed 90-route/174-exchange contracts remain the baseline. No field measurements, production deployment, provider activation or operating-system callback guarantees are implied by this slice.

## API contract

All five routes require an authenticated active driver and PostgreSQL migration 9; SQLite returns `409 presence_protocol_unavailable`. `GET /api/driver/presence` returns `offline`, `location_stale`, `online`, `busy` or `not_eligible`, never a location, with matching explicitly disabled. `POST /api/driver/presence/online` accepts `{commandId,deviceId,consentVersion:1}` and returns `{sessionId,leaseUntil}`. `POST /api/driver/presence/offline` accepts `{commandId,deviceId,sessionId}`. `POST /api/driver/presence/heartbeat` accepts `{deviceId,sessionId,seq}`. `POST /api/driver/presence/location` accepts `{deviceId,sessionId,seq,ageMs,latitude,longitude,accuracy?,heading?}` and reports acceptance or a stale, ordering, rate or outlier reason. It rejects preassignment collection when an active job exists; that job continues to use the installed `/api/location` route. IDs are UUIDs; sequences are positive safe integers. Location requests are also limited to 60 per minute, and the other commands to 30 per minute per route.

Verification: `tests/presence-migration.mjs` runs a synthetic local PostgreSQL version 8 to 9 upgrade twice and checks empty defaults, cross-driver session/fix rejection, logout cascade and user suspension. It does not test a presence API, transport behavior or client devices.

`tests/presence.mjs` exercises consent, idempotent replay across two API processes, a two-device lease race, expiry, heartbeat and fix ordering, freshness, outlier recovery, offline, logout and a changed vehicle document revision. These are synthetic loopback tests, not field or native-device evidence.

Independent Haiku review led to an absolute speed guard against the reported-accuracy bypass, legacy -1 sentinel handling, the permanent-driver-approval gate, shared rather than exclusive policy locks on presence reads, expiry/ineligibility cleanup, and commit of the legacy-custody inspection flag on refusal. The presence suite exercises each repair, including an actual scheduled cleanup and a concurrent shared-policy lock. This does not establish that a driver location is authentic.

A second review led to server-receipt fencing for speed, user-before-presence cleanup locking with skipped busy rows, removal of stale fixes during live heartbeats, and offline access after permanent approval is revoked. The dedicated tests are registered in `scripts/check-persistence.mjs`; the SQLite-first `npm test` gate intentionally does not require a running PostgreSQL server.

The existing active-job client now applies a five-second moving / fifteen-second stationary decision above the two-second transport floor, including failed or rejected attempts, and drops fixes older than 30 seconds or reported as mocked by Android. A restored native task cannot upload until the current app launch revalidates the account and active assignment; the tracking context is one envelope and startup no longer rewrites the session token. Session tokens and the tracking envelope use the SDK 57 `AFTER_FIRST_UNLOCK` accessibility option. These are client-side safeguards, not the missing assignment-epoch protocol or evidence of native delivery cadence. Background work may stop when the OS terminates the app, and a fresh foreground launch is required to reauthorize a restored task.

The presence controller starts only from explicit consent, persists pending command IDs before network calls, binds context to the current account and device, drops overlapping fixes instead of queueing them, and uses monotonic time for its local cadence. A fresh app launch never resumes an old presence session automatically. The foreground driver-work watch sends presence fixes only when current order status is known and no active job exists; logout, account changes, denied permissions and server refusal stop local collection. `requestBackgroundTracking` is a separate driver action and must be preceded by an explanation; a granted permission and enabled provider are prerequisites, not a promise of future callbacks. The local PostgreSQL client/API regression covers lost acknowledgment replay, offline, logout and separation from the customer live-map table.

The driver screen now mounts the consent and status card, with matching explicitly off. A separate, explained action requests optional background permission for active-job tracking; it does not guarantee OS callbacks. Preassignment presence is foreground-only: leaving the foreground stops the local timer and requests offline, and the server lease expires if the request cannot complete. Returning to the app requires a new online action. Permission prompts and provider checks are fenced against backgrounding, assignment, and loss of known order status; if a prompt changes app state the driver may need to tap online again. The customer-facing weak and stale thresholds are now 30 and 60 seconds respectively, following the Haiku UI review; these do not replace server-side authority or the presence fix's 30-second freshness limit.

The default 53-suite run, lint and typecheck passed with this slice. SQLite and PostgreSQL frozen-contract checks passed with the original 90 routes and 174 exchanges plus 25 additive boundaries. The PostgreSQL presence test also verifies an active job rejects preassignment fixes, SQLite reports the protocol unavailable, a pre-session fix is stale, and logout removes the latest stored fix.

Partial active-job hardening verification: `tests/pg-live-commit.mjs` exercises two parcels assigned at different times, a session deletion held open on a separate PostgreSQL connection while a location request waits, and post-commit/rollback live-watcher behavior. This is not a two-process assignment race or verification of the unfinished epoch/device protocol. The SQLite map suite and both frozen-contract checks also pass.

The existing `tests/pg-import.mjs` passed against dedicated loopback database `wp07_presence_test`: 29 legacy tables and 135 synthetic rows reconciled after `pg_dump`/`pg_restore`, with HTTP parity. Its initial run against the already populated shared test database timed out in `pg_dump`; the isolated database avoided the large shared catalog. `npm run lint` and `npm run typecheck` passed.
