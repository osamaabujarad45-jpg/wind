# WP08 backend: routing evidence and immutable quotes, corpus gate open

Migration 11 adds versioned `road_restrictions` and immutable `quotes` after migration 10. Restrictions are append-only rows keyed by `(restriction_key, version)` with directed LineString geometry (SRID 4326), affected services and vehicle classes, source, validity window, last confirmation, confidence, and the operator decision (`confirmed_prohibition`, reviewer, evidence reference, reason). A newer version supersedes an older one at read time; rows are never updated or deleted in place. Quotes store the customer, service, immutable itinerary and scope, ILS currency, exact minor-unit lines whose sum is the payable minor total, the tariff snapshot with percentages in basis points and a tariff version hash, routing and restriction revision identifiers, an ETA band, disclosures, and an expiry exactly 120 seconds after server creation. Quote rows are immutable except for a single consumption transition to a committed order. Orders gain a nullable `quote_id`; no existing identifier, status, or monetary output changes shape.

Feasibility is decided only from genuine evidence. The retained OSRM adapter supplies the candidate route line when it answers; otherwise the straight pickup-to-dropoff line is used and the quote is recorded as estimated. Directed crossings are computed in PostGIS against the latest valid version of each restriction: a confirmed prohibition blocks only when the geometry intersects the route, the restriction direction is traversed (bidirectional, or forward/backward by route progression along the geometry), and the restriction applies to all vehicle classes. A restriction scoped to specific vehicle classes cannot be confirmed applicable before a driver and vehicle exist, so it is recorded as uncertainty, as are nearby-but-not-intersecting restrictions, missing or stale evidence, and any routing-evidence query failure. No graph or provider version is recorded, because the retained OSRM adapter exposes no versioned release identifier; inventing one would fabricate revision evidence. Restriction coverage of a whole route is likewise not attested by any current source, so ordinary quotes are `uncertain` with an ETA band widened for that uncertainty, never `feasible`. Only a confirmed applicable prohibition is `infeasible`, and it cannot become bookable: `/api/price` refuses it and `/api/orders` re-evaluates current evidence inside the booking transaction before committing, so a prohibition that lands after a quote was issued still blocks that booking. The existing classifier in `server/domain/routing-policy.ts` is the single decision function; this packet wires it only to the crossings and revision facts above.

On PostgreSQL with migration 11, `/api/price` keeps its current response and adds `quoteId`, `quoteExpiresAt`, `currency`, `priceMinor`, `commissionMinor`, `tariffVersion`, `tariffBasisPoints`, the four revision fields, `etaBand`, `feasibility`, `reasons`, `disclosures`, `lines`, and `itineraryHash`. Configured tariffs, the flat parcel fare, night and Plus handling, and whole-ILS payable rounding are unchanged; line sums are exact minor units. Fields left unsupplied at preview time are stored as unspecified, never as a fabricated contact or note: booking may fill them in, but may not contradict a supplied value. `/api/orders` accepts `quoteId` instead of any client total (supplying `quotedPrice` or `price` with a quote is `400 quote_price_conflict`) and, inside one transaction, locks the quote, checks ownership, expiry (120 s), itinerary and scope equality including pins, contacts and recipient, re-checks prohibition, validates any promo under its row lock, inserts the order at the quote's minor-unit price, and marks the quote consumed. An expired quote is `409 quote_expired`, a changed itinerary `409 itinerary_changed`, reuse under a new command `409 quote_consumed`, and a pooled quote keeps the legacy `409 pooling_unavailable`. Requests without a quote keep the installed server recomputation and `price_changed` behaviour exactly, on both backends; SQLite, which has no quote tables, keeps the legacy price shape with no quote fields. Replaying a successful booking command returns its committed order without recalculating today's fare, including after the quote has expired.

## API contract

`POST /api/price` requires an active customer. On PostgreSQL it returns the legacy fields plus the quote fields above; an infeasible route is `409 route_prohibited` and no quote is stored. `POST /api/orders` with `{quoteId, requestId}` creates the order at the quoted price or fails with `400 invalid_quote`, `400 quote_price_conflict`, `400 invalid_phone`, `400 invalid_input`, `404 quote_not_found`, `409 quotes_unavailable`, `409 quote_expired`, `409 quote_consumed`, `409 itinerary_changed`, `409 route_prohibited`, `409 pooling_unavailable`, or the existing promo failures. The same `requestId` with the same payload replays the committed order; the same `requestId` with a different payload is `409 idempotency_conflict`. Partner, legacy `quotedPrice`, and smart-recommendation booking paths are unchanged.

Verification: `tests/quotes.mjs` covers quote creation with versions and minor units, whole-ILS rounding, booking and consumption, replay after expiry, expired and changed-itinerary rejection, quote-bound total refusal, tariff-change immutability against the legacy `price_changed` path, legacy `quotedPrice`, the promo last-budget race, the night flag, and single-counted slow-checkpoint delay. `tests/quotes-routing.mjs` covers provider-unavailable uncertainty with booking still allowed, a confirmed prohibition blocking and unblocking, same-city and rural-pin handling, and stale evidence staying uncertain. A throwaway probe (not retained) additionally verified reverse-direction, expired, other-service, and vehicle-scoped restrictions do not block, a prohibition inserted after quoting blocks at booking, and pin or contact contradictions are rejected while an unsupplied contact can be filled in. `tests/routing-policy.test.mjs`, `node scripts/check-contracts.mjs` (174 exchanges, schema identical, only the SQLite quote exchange re-recorded to its legacy shape), `node scripts/check-persistence.mjs --filter=quotes` on a fresh loopback database, the full `npm test` gate (57 suites), `npm run lint`, and `npm run typecheck` all pass. Two pre-existing mojibake placeholders for erased account names in `server/main.ts` were repaired to the em dash the existing tests assert; no other unrelated behaviour changed.

Open launch gates, recorded as not met: the versioned corpus of at least 100 adjudicated origin/destination cases per launch area does not exist, no operator has signed off the restriction set, its provenance, review cadence, or confidence coverage, and no actual travel, loading, or checkpoint times have been collected or published. Until those exist, quotes remain honestly `uncertain`, restriction evidence comes only from operator-entered rows, and this packet must not be described as route validation. Quote-bound booking is available only on PostgreSQL with migration 11; production PostgreSQL cutover remains gated by the earlier packets.
