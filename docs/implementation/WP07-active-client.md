# WP07 active-job GPS native client experiment

The native client uses the fenced protocol only when both `__DEV__` and `EXPO_PUBLIC_TEST_ACTIVE_GPS=1` are set. The server must independently run with its test-only flag and migrated PostgreSQL; an unavailable or conflicting session fails closed. This is not a production rollout. Default native and web transports remain legacy; web cannot upload for a driver with an active fenced session while the server test flag is enabled.

Foreground reconciliation requires a successful current order list, permission, enabled services and an active driver. It inspects the server generation and persists the exact replacement command before sending it. A lost response is retried with the same candidate only after fresh foreground validation of the same account and complete order IDs. Lifecycle, account and assignment changes invalidate pending responses. The returned complete assignment epochs accompany every fix. Native callbacks never acquire sessions. Rejected fenced uploads stop local sharing and require subsequent foreground reconciliation; they do not fall back to legacy.

The device identifier is generated once and retained in SecureStore; platform secure-storage persistence across uninstall may vary. A single persisted sequence record reserves each number before upload, and a serial queue prevents overlapping callbacks from reusing it. Gaps after crashes, failed sends or cancellation are intentional. A persisted candidate and sequence are scoped by session and account, and a server generation change rejects obsolete acquisition retries. Coordinates themselves are not queued.

The tests use mocked native APIs and server responses; they do not establish real-device background behavior, persistence across OS reinstall, or production readiness. Web remains legacy and receives no fencing guarantees. The server can remove the shared pin when assignment membership changes until a fresh foreground session sends an accepted fix.

Review fix (Muse Spark 1.3 review, verified by regression tests): a validated acquisition now clears its persisted candidate in acquireActiveGps, so the next foreground start inspects fresh instead of replaying the spent command and failing 409 every other start. Sequence is per-session: a fresh session restarts from the server-returned sequence, and a failed delivery's gap stays in its previous session. Covered by tests/active-gps-client.test.mjs (fails on the pre-fix code) and tests/active-gps-native.test.mjs.
