# WP07 active-job GPS: experimental test-only protocol

Migration 10 adds an experimental PostgreSQL active-job fence. Both session acquisition and fenced uploads require `NODE_ENV=test` and `WIND_TEST_ACTIVE_GPS=1`. They return 409 `active_gps_unavailable` otherwise, including in production, SQLite and unmigrated PostgreSQL. Migration alone does not block legacy writes. No production activation or client integration is authorized by this experiment.

In a test environment with the flag enabled, `POST /api/location/session` with `{deviceId}` inspects the same-device session and returns `{sessionId:null|UUID,generation}`. A foreground replacement sends `{deviceId,sessionId,previousSessionId,expectedGeneration}` using a fresh session UUID and both values returned by inspection. A compare-and-swap failure returns 409 `active_gps_session_stale`; another device or authentication session returns 409 `active_gps_session_conflict`. A successful replacement returns `{sessionId,generation,seq,assignments:[{orderId,assignmentEpoch}]}`. Identifiers and epochs are safe integers and the next upload sequence must exceed `seq`. An identical acquisition can be replayed only while its generation is current; membership changes and revocation invalidate it. UUIDs cannot be reused. Only foreground code should inspect or replace sessions, and it must discard a response after account, lifecycle or authorization changes.

The durable driver generation advances on session replacement, assignment membership changes, authentication-session deletion and account ineligibility. Thus a delayed acquisition whose previous session was null cannot become valid again after logout. Current active assignments are locked before the driver account and re-read under the account lock. The existing assignment guard also takes the driver account lock. A user-first database transaction can invert this order. The API bounds its lock wait and returns retryable 503 after rolling back; deadlock victims also return 503. A deterministic test verifies that a subsequent retry can succeed. This experiment does not promise uninterrupted tracking.

With the test flag enabled, `POST /api/location` accepts existing coordinates and extras with `activeGps:{deviceId,sessionId,seq,assignments}`. The assignments must be the complete exact snapshot returned by foreground acquisition. Stale session or device, old sequence and a changed assignment set return HTTP 200 `{ok:true,accepted:false,reason}` with `session_stale`, `sequence_old` or `assignment_stale`. Assignment mismatch consumes the sequence. Legacy requests for a driver who has acquired a fenced session return 409 `active_gps_required` while the test flag is enabled; this explicit coexistence restriction prevents a legacy fix from overwriting fenced data. Legacy callbacks have no assignment identifier and are not made safe by this protocol.

Logout and account ineligibility remove the fenced session and its stored pin. Assignment-set changes invalidate the pin for an opted-in driver; replacing the session also removes it. A new active assignment increments the order epoch even if the driver is unchanged. These invalidations can temporarily remove the pin for other parcels until a new accepted fix. Device UUIDs are identifiers, not attestation, and GPS accuracy and OS callback delivery remain untrusted. The session-ID registry and driver generation have no retention policy. Disabling the test flag can permit legacy writes again; a later test re-enablement must start with a clean isolated database.

`tests/active-gps.mjs` exercises a two-process sequence race, an inverted-lock timeout and retry, a held assignment transaction against an upload, a held logout transaction against an upload, stale acquisition after logout and new login, device conflict, assignment changes, same-driver reactivation and the disabled-flag behavior. PostgreSQL contract, migration and isolated legacy import tests, SQLite frozen contracts, lint and typecheck also passed. These synthetic tests do not establish native-device behavior or production readiness.
