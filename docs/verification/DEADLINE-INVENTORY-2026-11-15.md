## Broadcast coverage and remaining acceptance

`plugins/with-deadline-wake.js`, registered in `app.config.js`, declares the app-owned, non-exported `DeadlineWakeReceiver` for BOOT_COMPLETED, USER_UNLOCKED, TIME_SET, TIMEZONE_CHANGED and MY_PACKAGE_REPLACED. `modules/deadline-wake/` is a local Android Expo module discovered from its own package/module configuration; generated root `android/` and `ios/` files are not hand-edited.

The native module stores only an opaque session namespace, known recovery slot names, deadline/monotonic/boot anchors and generation markers in an atomic no-backup file. It restores one inexact `ELAPSED_REALTIME_WAKEUP` alarm for the earliest valid existing envelope expiry. Clock-forward expiry and ambiguous clock rewind across reboot become pending foreground reconciliation; same-boot monotonic remaining time prevents extension. Expired identity tombstones prevent a reopened old record from reviving an expired native deadline. Duplicate wakes coalesce; cancel/logout remove their registrations, and stale alarm/acknowledgement generations cannot clear a replacement wake. No token, address, PIN, location, command body or request ID is stored by this module.

Receivers never start JS, a service, location, presence or a network request. `src/deadline-recovery.ts`, the scope-checked storage bridge and `SessionProvider` expose/consume pending wake state only in an active foreground session. A wake clears displayed saved summaries and fetches current `/me` and runtime configuration; it never calls a mutation or driver-command replay, changes a request identity, assumes an unknown booking absent, or revives an assignment. Existing driver recovery retains its screen focus/identity/explicit-Retry and receipt/actor/assignment guards.

`tests/deadline-recovery.test.mjs` covers foreground duplicate/session/background/failure fencing, protected-store expiry hooks and scheduler-failure preservation of unknown commands, slot cancellation/logout and CNG manifest registration. Local-module `DeadlinePolicyTest.kt` covers actual Kotlin scheduling, reboot/unlock/package idempotence, clock changes, expiry tombstones, bounds and scope/ack/cancel fences. These checks were authored for remote execution; this inventory does not claim they passed. Before declaring A14 complete, run remote lint/typecheck, Node checks, Expo autolinking/CNG and native Gradle tests/build. Actual OS delivery, process death, reboot, time/timezone changes and package replacement still need a freshly identified native QA build and the physical phone. Inexact alarms can be delayed by OS/battery restrictions, and force-stopped apps require user launch; no guaranteed background delivery is claimed. Expo Go, web and iOS retain their existing foreground recovery without this Android module.
