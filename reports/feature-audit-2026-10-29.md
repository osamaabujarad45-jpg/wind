## Explicitly absent or conditional

The historical capability map records no in-app digital wallet/card payment, cash-on-delivery payout ledger, delivery photograph, automatic driver-document upload, tipping, cancellation fee, pooling or customer-defined multi-stop route. Phone/email verification, native push and road routing need service configuration. Newer PostgreSQL-backed capabilities are gated; their tests do not mean that the production service has them switched on.

## This pass

- `npm run lint` and `npm run typecheck`: passed before and after the first client fix.
- The initial `npm test` run reached the PostgreSQL logging test, where a shared migration lock timed out; the specific test was reproduced and fixed. Full rerun pending.
- `npm run test:readiness`: nine groups passed using the existing local web export; repeat on a fresh export is needed.
- The first `npm run test:load` ran at the same time as other tests and an emulator. It recorded zero unexpected responses/timeouts, but the 60-concurrency read and mixed p95 were 690 ms and 740 ms, above its 500 ms gate. Repeat without competing work before drawing a capacity conclusion.

- Android emulator booted but its accessibility snapshot helper timed out. iOS simulator is unavailable on this Windows host. Neither result establishes native-device readiness.
- Fixed cached order data remaining visible after definitive access refusal; focused browser regression initially failed and then passed on the rebuilt web bundle. `npm run test:access` provides a dedicated fresh-build check.

The 29 October `release-readiness-2026-10-29.md` documents missing or unverified production routing, identity, push, support, backups/alerts and real customer/driver delivery. No production changes or live orders were made in this audit.
