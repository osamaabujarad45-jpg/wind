## Azure choices and remaining acceptance

- A read-only inspection of the currently selected Azure subscription on 28 October 2026 found a Container App named `wind-api`, but its revision list was empty and its public endpoint returned Azure's unavailable page. The inspected app configuration did not include Entra, ACS, Azure Maps or PostgreSQL settings. No Azure Maps accounts or Communication Services resources were listed in that subscription, and no app registration named exactly `Wind` or `Fastship` was found in the current directory. These observations do not establish what exists in other subscriptions, tenants or differently named registrations; they do establish that this particular deployment was not serving the application during the check. No Azure deployment was made.
- Microsoft Entra External ID and Azure Communication Services integrations are configuration-gated. Tenant registration, real verified claims, SMS delivery to local carriers, provider costs and failure handling must be checked with an actual authorized Azure tenant and real numbers before enabling them. SMS in External ID is documented as a second factor, not a primary sign-in method.
- The current map stack uses MapLibre/OpenFreeMap, Apple Maps on iOS, and OSRM routing. Azure Maps was researched but not activated: coverage and route/traffic quality for the service area have not been demonstrated, and switching could alter checkpoint-avoidance behavior. [Azure Maps routing coverage](https://learn.microsoft.com/en-us/azure/azure-maps/routing-coverage) varies by region; [Azure Maps Route 2025 API](https://learn.microsoft.com/en-us/rest/api/maps/route/post-route-directions) is the current API to evaluate. The [older v1 route API](https://learn.microsoft.com/en-us/azure/azure-maps/migrate-route-v1-api) is deprecated.
- The default production SQLite deployment still uses legacy assignment and ride flow. PostgreSQL-only presence, active-GPS fencing, measured eligibility, dispatch and boarding protocols remain gated; tested PostgreSQL code is not automatically active in production. A safe cutover needs migration, parity, rollout and operational acceptance.
- iOS MapKit's `onMapReady` signals the start of rendering, not proof of usable tiles. Offline/blank-tile fallback and the native map-in-scroll-sheet gesture need an iOS simulator or device. iOS simulators are unavailable on this Windows host.
- Contact verification is not automatically guaranteed for every existing password account. Accounts with unverified matching contacts are not auto-linked; collision recovery and a real proof workflow need operational acceptance. Existing sessions with no idle timestamp may be required to sign in again once the idle limit is deployed; their previous activity cannot be reconstructed reliably.
- Live provider integrations, actual payments, push delivery, background tracking and performance under realistic load and mobile OS restrictions have not been demonstrated end-to-end. A passing local suite is not evidence of production scale or a 100% quality guarantee.
