# Wind app audit — 1 November 2026

What this repo does: Wind is an Arabic-first parcel-delivery app with customer,
driver and administrator roles. One Expo SDK 57 app uses a Node API with SQLite
or PostgreSQL persistence. This review assumes multiple simultaneous customers
and couriers, intermittent phone connectivity, and retries after lost replies.

Scope: the current working tree, including the new uncommitted OpenCode feature.
Existing research/documentation edits were preserved. This is a risk-based review
of the whole app, not a certification that every line, locale and device is correct.
No production data, external job execution, deployment, commit or push was used.

## Skill order and conflicts

The following applicable skills were loaded and used in this order. Their
checklists overlap; findings were consolidated instead of applying conflicting
output formats or repeating the same changes.

1. `expo:expo-overview`: establish SDK57, platforms and native/web boundaries.
2. `ponytail:ponytail-audit`: inventory requirements, entry points and high-risk flows.
3. `code-review`: separate standards and specification reviews in independent
   agents. The review basis is the whole working tree against AGENTS, README,
   SYSTEM, the relevant SPEC files and frozen compatibility contracts; it is
   broader than this skill's usual branch-only diff. No issue tracker is needed.
4. `code-review-and-quality`: correctness, simplicity, architecture, security,
   performance, dependency and verification checks.
5. `security-and-hardening`: trust boundaries, authorization, sensitive data,
   command execution, concurrency and dependency-advisory triage.
6. `api-and-interface-design`, `api-testing`: installed/additive route contracts,
   ownership, error boundaries, idempotency and negative cases.
7. `performance-optimization`: existing bounded-load harness and resource bounds.
8. `frontend-ui-engineering`: loading/failure states, controls, localization,
   product copy and mobile behavior.
9. `a11y-playwright-testing`: accessibility checklist and named controls during
   physical-browser checks; no full axe/TalkBack/WCAG certification is claimed.
10. `qa-manual-istqb`: risk-based coverage, regression selection and evidence.
11. `ponytail:ponytail-review`: review fixes with connected code and executable
    regressions. `git-workflow-and-versioning` supplied change hygiene only.

The user's fix-in-place instructions take precedence over audit skills' usual
read-only behavior and skill-level approval prompts for reversible fixes. The
audit phase identified issues; remediation followed it. No commits were made.
AWS, token/smart-contract, offensive security and third-party platform audits do
not apply to this app's current Azure/Expo/Node implementation and were excluded.
Compressed-writing review variants were not used to replace the requested evidence.

## Confirmed findings and fixes

Each entry records issue → change → verification. P1 means a significant
correctness/security defect; P2 means a behavior or verification defect.

1. **P1: API startup fails under strip-only Node.** OpenCode used unsupported
   TypeScript constructor parameter properties → replaced them with explicit
   fields/assignments → `opencode.test.mjs` starts the actual Node API process.
2. **P1: private CLI jobs exposed to customers/drivers.** Job reads lacked admin
   authorization → guard every job route → customer/driver GET and POST denial,
   anonymous-boundary and admin tests.
3. **P1: unsafe/unbounded request-triggered CLI execution.** The feature could
   download/run a CLI, crash on a missing executable and grow output indefinitely
   → local explicit opt-in, installed executable, production refusal, spawn error
   handling, output/time bounds and launch after commit → disabled/production,
   input, missing executable and continued API-health regressions. A production
   isolated runner is still required before enabling this feature there.
4. **P1: CLI writes/reads fail with SQLite/UUID IDs.** SQL used PostgreSQL-only
   casts and the generic route matcher accepted numeric parameters → portable
   binds and explicit UUID-capable captures → actual SQLite job API regressions.
5. **P2: optional CLI history changes delivery-schema/import contracts.** The new
   table was always added and included in legacy snapshot import → create it only
   for enabled local runs and exclude operator history from delivery import →
   frozen SQLite schema and endpoint compatibility checks; enabled job regression.
6. **P1: concurrent password resets reuse one code.** Code was read then deleted
   without checking the claim → atomic conditional consumption and attempts →
   two synchronized reset requests must return one success and one rejection in
   both SQLite and PostgreSQL fixtures.
7. **P1: uncertain booking recovery can select another order or enable a
   duplicate.** Matching used mutable fare/notes/pins and elapsed time → exact
   account-owned command receipt; missing/malformed receipts stay unknown, with
   the same request ID available for retry → similar orders, changed order,
   receipt ownership, invalid ID and role regressions in `booking-auth.test.mjs`.
8. **P1: inaccessible booking storage looked empty.** Best-effort reads masked
   denied storage → required restoration read fails closed → booking guard and
   executable required-storage tests.
9. **P2: Google routing rebills on foreground.** Initial-focus policy also allowed
   repeated foreground fetches → separate initial load from foreground refresh
   → `api-focus.test.mjs` exercises focus/background/foreground and changed URLs.
10. **P2: Google SDK Retry cannot recover a timed-out script.** Retry sees the old
    tag and waits forever → shared callback-based loader removes failed scripts,
    deduplicates in-flight loads and reuses an initialized SDK → executable timeout,
    retry, network failure, callback and reuse tests.
11. **P2: maps can remain blank indefinitely without tiles.** Construction was not
    followed by a tile deadline → finite failure deadline for route/pin maps;
    failed pin attempts ignore late events; retry clears readiness → map lifecycle
    tests with controlled SDK/timers.
12. **P2: stale initialization and leaked picker DOM/listeners.** Geometry/GPS
    changes during SDK loading were lost and retries accumulated map nodes →
    latest committed values, listener/DOM disposal, controlled picker recentering
    and no construction after unmount → executable lifecycle tests.
13. **P2: denied map-preference storage throws or overwrites a current choice.**
    Direct localStorage calls could fail → existing safe storage helpers and
    cached-choice precedence → denied getter/write lifecycle regression.
14. **P2: the Google pin picker requested a user-location display unnecessarily.**
    It already receives an explicit center → removed `showsUserLocation` from the
    Google picker → source/type/build verification; no real-key native run claimed.
15. **P2: onboarding exposes English developer-model details.** Five slides
    included model/provider environment information → restored three localized
    delivery slides and removed dead artwork → source review, lint/typecheck and
    bundle build; no customer-facing implementation details remain in those slides.
16. **P2: schedule memo warning obscures the time dependency.** The bucket was an
    unused memo dependency → use its stored timestamp to compute slots → lint and
    existing scheduling regression.
17. **P2: new API routes lacked additive contract coverage.** Inline registration
    changed the frozen installed inventory and OpenCode was not inventoried →
    separate receipt registrar, explicit additive inventories and a UUID sample
    for regex paths → 90 installed + 82 additive boundaries, 21 transitions and
    174 exchanges pass without rerecording the installed fixture.
18. **P1: malformed URL decoding can stall the JavaScript thread.** Vendored
    decoder 0.5.0 still had quadratic replacement of distinct encoded runs →
    backport the upstream single-pass fix while preserving CommonJS semantics →
    Arabic/query-array and 32,000-distinct-run regressions under a process deadline.
    **CI follow-through:** npm still reports
    the old decoder version after the backport → retain the native audit and raw
    counts, accepting only this exact advisory chain when the resolved and vendor
    sources match the pinned reviewed SHA256; unknown high/critical findings,
    altered bytes and native/network errors still fail → executable acceptance and
    rejection fixtures plus a real native-audit gate run. Git attributes preserve
    the pinned decoder bytes across Windows/Linux checkouts.
19. **P1: public map fragment colors can inject SVG markup.** The map page is
    exempt from the web script CSP because of its inline module, and arbitrary
    `config.colors` values reach SVG `innerHTML` → accept only the known palette
    keys with strict six-digit hex values and fall back per key → executable
    malicious-fragment markup regression and updated physical map verification.
20. **P2: completed history repeats destination-capability database queries.**
    Each row checked schema availability even when its status already prevented
    destination changes → check existing eligibility first, preserving the exact
    returned data → existing destination-change/contracts regressions and measured
    60-reader/full-load reruns. No benchmark threshold was loosened.

## Map integration assessment

Baseline renderers are MapLibre/OpenFreeMap on web and Android WebView, Apple
Maps on iOS. Google renderers require baked platform capability plus an explicit
preference. SDK57's documented `react-native-maps` version is 1.27.2, matching the
project ([versioned Expo documentation](https://docs.expo.dev/versions/v57.0.0/sdk/map-view/)).
Native keys are configured through the plugin; server routing keys are separate
from public browser keys. Source checks cannot prove cloud-side key restrictions.

Reviewed provider provenance restrictions, OSRM/Google routing policy, meaningful
billable reroute triggers, public baseline tracking, route/approach geometry,
checkpoint closures, stale-fix presentation, movement/heading interpolation,
camera follow/recenter, localization, tile readiness, retries, picker confirmation
gating and WebView navigation/message handling. Existing map/routing tests and
new loader/lifecycle tests cover these contracts. The standard entry wrappers
key Google route maps by pickup/dropoff coordinates, rebuilding endpoint markers
when an address changes.

No new map provider or library was added. A real Google-keyed native APK, real
Google quota/auth failures, iOS hardware, background battery/thermal behavior,
real checkpoint data and production route quality remain separate acceptance work.

## Measured performance change

The first noncompeting full load run narrowly failed the 60-reader target
(p95 507.47 ms; populated jobs 509.51 ms). Repeating only that same phase before
the code change measured 499.44 ms, showing a small amount of variation around
the target. The redundant per-history-row schema lookup was then removed by
moving the existing eligibility guard before it.

The identical `--phase=read-60` command measured 452.25 ms after the change,
an improvement larger than the observed pre-change variation. The subsequent
full run passed every gate, with 60-reader p95 402.67 ms and populated jobs
406.84 ms. It recorded zero unexpected errors/timeouts, intact constraints,
and 481 idempotent bookings stored once. Expected location throttles remained.

![Same-command latency measurement](../.artifacts/audit-2026-11-01/performance.svg)

This is a bounded synthetic test on a shared k5 host; unrelated host work was
not stopped. It does not establish a production capacity limit. No latency
budget, assertion, required work or authorization check was removed.

## Remaining limitations and dependency disposition

See [dependency triage](dependency-triage-2026-11-01.md). Raw npm audit reports
29 package entries: three high entries from the patched decoder advisory,
25 moderate toolchain entries from glob/minimatch advisories, and one low entry
from the previously source-patched deepmerge package. Version-based raw audit
is not clean. Toolchain advisories remain unresolved; the app API does not expose
build/lint glob patterns. Incompatible major overrides were not forced.

No full TalkBack/VoiceOver, axe scan, complete large-text/reflow matrix or iOS
device test was performed. Phone-browser rendering does not validate the rebuilt
native APK or locked-screen background collection. The review does not certify
provider delivery, public-launch readiness or production capacity.

Verdict: the 20 confirmed findings are remediated and verified within the scope
above. Remaining toolchain advisories and device/provider/accessibility limits
prevent unconditional public-launch approval. No commit, push or deployment was
performed.
