## Changes

Each entry records **issue → change → verification**. The final execution record below distinguishes completed checks from acceptance limits.

1. **Renderer failures never reached fallback policy →** shared `MapProviderBoundary` now owns provider selection, generation-fenced failure reporting, finite fallback, terminal diagram/Retry and baseline-only public maps. A retry creates a new attempt; old readiness/center/failure callbacks cannot revive or poison it. Geometry consumers honor a null renderer, and retained approach state is scoped to renderer, order, assignment, stage and target. **Verification:** provider-policy regressions, real boundary callbacks in the lifecycle harness, map/provenance/security suites and browser map scenarios.
2. **Camera abstraction was unused and adapters drifted →** removed the test-only viewport module, retained the shared framing/math helpers, included road geometry in native framing, stopped native follow on physical touch (including pinch), and corrected Google web gesture/recenter/reduced-motion behavior. Stale Google markers fade and lose approach geometry. Android initializes a driver from its fragment without requiring a later injection; failed page attempts cannot announce late readiness. Pin retries reset readiness and preserve the chosen center. **Verification:** map math, adapter/lifecycle harnesses, browser map/bridge/pin scenarios and platform exports. Native iOS interaction is not physically verified.
3. **A rejected proof advanced recovery revision while the screen reused the old one →** every new durable driver intent fetches a fresh authorized snapshot; action replies retain metadata after recording the receipt. Definitive refusals refresh before another input; ambiguous deliveries preserve the original identity. Receipt HTTP status, account/focus/order/assignment fences and protected PIN-revision binding are retained. Proof input is cleared when its actor, assignment, status or challenge changes, and unused codes are not sent to later actions. **Verification:** driver-command/recovery API regressions, proof replay counts, wrong-then-correct completion and browser handover journey.
4. **Offer presentation lacked a relative window and verb-specific recovery →** negotiated journey data provides issue/expiry/window fields and ETA metadata. Accept/decline errors retain their installed `error` and gain a redacted typed classification. Acceptance resamples server time after lock/eligibility waits. Paginated cards and detail actions consume the protocol; lost acceptance replies reconcile current assignment without automatically resending. **Verification:** pure/wire tests, PostgreSQL journey/dispatch/race suites, installed contract fixtures and browser journeys.
5. **Boarding lacked policy, issuance, revision and verified metadata →** migration 29 adds nullable issue/verification instants and a nonnegative revision, with historical timestamps left unknown. Same-assignment initialization no longer resets attempts. Only the authorized customer gets a displayable PIN. Negotiated admin rotation changes the code, checks assignment/revision and records its reason without the PIN. Stale proofs cannot spend the replacement challenge's attempts. Successful start records verification in its transaction. **Verification:** real PostgreSQL journey/lifecycle/race tests, migration rerun and missing-migration cases, role redaction, lockout and installed SQLite/PG compatibility.
6. **ETA ranges could outlive their calculations or starting fixes →** versioned seconds-based range/basis/accuracy/validity projections preserve quote/offer timestamps. Uncalibrated estimates remain `unknown`; straight-line fallback is `low`. OSRM cache calculations expire after 30 seconds without being rejuvenated on reads. Private/public approach displays expire using monotonic time and fix freshness; shared-run/context changes suppress arrival claims. Paid Google expiration triggers no new bill. Booking quote ETA expires without falling back to its stale scalar. **Verification:** exact-boundary/invalid-value/clock-jump tests, route/Google/customer-location suites and browser tracking journeys. Fixtures are not real traffic or calibration evidence.
7. **Waiting and fare explanations lacked a stable contract →** waiting end is projected from the existing arrival/grace instant, without introducing fees or paused clocks. Accepted destination changes persist before/after gross, discount and due amounts in integer minor units, using checked PG columns where present. PostgreSQL emits one transactional `fare.changed` event. Authorized snapshots show one stable change ID; installed event consumers filter the new family while advancing over scanned cursors. Public shares expose no fare history. **Verification:** SQLite destination tests, real PostgreSQL consent/replay/event-cursor tests, money boundaries and unchanged frozen exchanges.
8. **Lint and stale harnesses blocked honest gates →** session timing begins in an effect, unused imports were removed and recovery dependencies now represent actual identity invalidation. Deployment tests execute the transitive runtime closure and prove missing packaged sources prevent isolated boot. Map harnesses stub current imports and exercise real callbacks. Scenario fault injection matches paths with negotiated queries while preserving route/unroute identity. **Verification:** lint, both typechecks, full integration/persistence gates, isolated artifact boot and browser scenarios.
9. **k5 verification setup was incomplete →** preserved the original planner snapshot, created `C:\wq-maps-impl-20261101`, verified the matching dependency lock, used the installed pinned Bicep executable, and restored a separate disposable PostgreSQL fixture from the synthetic archive after fresh initialization and the old cluster's recovery failed. ## Protocol and rollout

- Clients negotiate `journeyProtocol=1` separately from recovery, capacity and durable-event protocols. Unsupported domains/old servers keep legacy behavior; new actions do not silently downgrade.
- Migration 29 is source preparation only. It was applied exclusively to disposable test schemas. SQLite has no new migration. Migration capability does not activate dispatch, boarding, payments or Google.
- Existing parcel states, tariffs, money representation, consent, public tracking limits, production gates and encrypted bounded recovery remain authoritative. No new dependencies were added.
- Broader reference ideas with undefined product semantics remain excluded: night/risk PIN policies, automatic rotation, QR, public offer expiry/ack endpoints, timer fees/pauses, fabricated progress percentages and new infrastructure.
