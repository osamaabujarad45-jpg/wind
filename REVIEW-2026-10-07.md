# Code review — 7 October 2026

Reviewed the server routes, authentication and role checks, order/pricing/cash flows,
client request/session handling, configuration, release inputs, dependency audit and
existing automated coverage. This is a source review and regression pass, not a
guarantee that every possible defect has been eliminated.

## Fixed

- Booking could outlive its customer's authorization while awaiting road routing.
  The handler now checks the live session, role and account status again before
  creating either an order or its idempotency record. Eight isolated integration
  cases revoke, block, change role or delete the account during that await, with
  and without a command ID. The original code failed the logout case.
- Null or non-string upstream error payloads could throw a TypeError instead of
  preserving the HTTP error. The client now returns its normal ApiError and status.
- Updated compatible shell-quote/source-map-js patches and replaced xcode's
  vulnerable UUID 7 dependency with UUID 11.1.1. UUID 11 retains CommonJS support;
  an xcode project-ID generation check verifies the actual consuming interface.
- Android release version advances to 1.0.10, code 11.

## Validation

- Full `npm test`, TypeScript and Expo lint passed.
- Production Expo web export passed.
- Browser checks cover Arabic/English sign-in, home, parcel booking, tracking,
  receipt, driver jobs and administration, plus driver location/privacy lifecycle.
- Live databases were encrypted and restore-verified before deployment.
- Deployment IDs and final live checks are recorded in the workspace report.

## Remaining dependency advisories

The audit still reports 23 affected package entries (20 high, 3 moderate, zero
critical), originating in three upstream issues. Many entries are ancestors of
the same vulnerable package, not distinct vulnerabilities.

- [braces GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm):
  no patched version published; used by Metro/tooling.
- [node-forge GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv):
  no patched version published; used by Expo signing tooling.
- [decode-uri-component GHSA-vcc3-ghjq-m6fr](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr):
  the 0.5 fix changes to ESM and breaks the CommonJS interface consumed by the
  installed query-string/Expo Router. A forced override was tested and reverted.
  This remains relevant to malformed client deep links until the upstream chain
  supports the fixed decoder.

The deployed Node API runtime contains no npm dependency tree; it uses Node's
built-in HTTP, crypto and SQLite modules. The client/development dependency risks
remain tracked; they are not described as resolved.

No Android phone was attached during this review. Signed artifacts can be checked
for signature and production endpoints, but installation behavior remains unverified.
